# Preview 与 Production 职责界定

- 日期：2026-09-15
- 来源：Steven 与 Codex 关于所有工作流开发范围、Preview 和 Production 分工、参数与费用处理的讨论。
- 性质：讨论结论归档，记录目标职责、功能边界与完成定义，供后续设计和验收引用；不代表这些功能已经实现、发布或通过真实生成验收。
- 当前实现与证据：[PROJECT_STATUS](../PROJECT_STATUS.md)。实施安排：[ROADMAP](../ROADMAP.md)。
- 当前落地规范：[工作流 Preview 与 Production 统一需求规范 v2](../requirements/2026-09-15/workflow-preview-production-spec-v2.md)。本文保存职责讨论结论，不代表代码、生产开放配置或付费执行已经变更。

## 1. 核心结论

**Preview 负责把“准备生成什么、参数是否有效、预计花多少钱、还有哪些问题”检查清楚；Production 负责按确认后的请求调用正式接口，完成生成、交付和费用结算。**

所有纳入本期开发的工作流，都以具备这两种模式为完成目标。仅有 Preview，代表该工作流完成了部分功能。不能把“此前只有某一工作流有正式验收记录”变成其他工作流长期只做 Preview 的产品限制。

用户操作保持一致：先 Preview 看清楚，再 Production 正式生成。

## 2. 共同基础与交互

同一张 ComfyUI 画布、同一份生成请求，可以在两种模式之间切换。请求包括：

- 工作流类型：文本、参考图、首帧、首尾帧、多参考、视频编辑、视频延长、音频参考等。
- 素材及其用途、数量和顺序。
- Prompt。
- 输出时长、比例、分辨率及该工作流允许的其他参数。

两种模式采用同一套服务端参数规则和价格计算规则。Production 使用经过预检和确认的参数，不能悄悄改回固定 5 秒、固定分辨率或其他默认值。

界面保留 `Preview` 和 `Production` 两种模式。`Preflight` 是 Preview 形成的预检记录，以及 Production 内部的复验步骤，无须增加第三种用户操作模式。

默认使用 Preview。预检通过后，由用户明确选择 Production 并确认本次生成；不得自动切换或自动提交。

## 3. Preview：检查并形成可确认的请求

### 3.1 应完成的功能

| 功能 | 职责 |
| --- | --- |
| 本地素材检查 | 检查文件是否存在、能否读取和解析，提取实际类型、尺寸、时长等信息，计算文件内容哈希 |
| 服务端规则检查 | 检查工作流、素材角色与数量、顺序、参数组合，以及模型支持范围 |
| 请求摘要 | 展示本次素材、Prompt、模型、工作流和输出参数，以及影响结果的其他选项 |
| 费用预估 | 根据本次输出参数、输入视频时长等计费因素和适用价格规则计算估算金额 |
| 正式提交条件提示 | 展示当前是否允许正式提交，以及权限、额度、暂停或功能未完成等原因 |
| 预检记录 | 保存请求摘要、素材哈希、规则与定价版本、有效期，并绑定当前账号，供正式提交复验 |

本地插件负责读取文件；公司 Backend 负责统一规则检查。完整 Preview 必须完成服务端检查。文件尚未上传时，服务端应注明素材信息来自客户端，不能声称已独立检查实际文件内容。

### 3.2 副作用边界

- 不上传素材本体到公司存储或 Provider；不发送文件 Base64、缩略图或供服务端拉取素材的 URL。
- 不调用视频生成 Provider。
- 不创建可被 Worker 领取的任务、付费 Attempt 或预算预占。
- 可以保存不可执行的预检记录。
- 不产出生成视频，不代表素材已通过 Provider 内容审核，也不保证正式生成成功或创意效果。

这里的 Preview 是生成前预检。官方接口中的 Draft／样片属于真实生成；若以后接入，应归入 Production 并明确费用。

### 3.3 报告分开表达请求有效性和生产准入

报告至少包含两个独立结果：

```text
请求检查：通过 / 不通过 / 未完成
正式提交：可提交 / 暂不可提交，并说明原因
```

例如，请求参数正确但额度不足时，应显示：

```text
请求检查：通过
预计费用：按本次参数计算的估算金额
正式提交：暂不可提交，当前可用额度不足
```

额度不足、Production 暂停或当前账号没有生产权限，可以作为报告中的阻止原因，不必阻止请求本身的检查。身份鉴权仍然保留；服务端不可达、鉴权失败或必要检查未完成时，不能显示完整预检通过或允许正式提交。

### 3.4 估算结果的表达

- 能计算时，说明估算金额、计算依据及适用价格。
- 只能给范围时，展示范围及原因。
- 缺少必要数据时，明确显示“暂无法估算”和缺失项。
- 不把固定回退金额展示成“按实际参数计算的费用”，也不把未知金额展示成 0 元。

预估值不是最终费用，Preview 的额度检查也不是预占或正式准入承诺。

## 4. Production：正式生成、交付和结算

### 4.1 执行流程

```text
用户明确确认本次请求
→ 复验预检记录和当前权限
→ 上传素材、验证实际内容（或校验并复用已有素材）
→ 最终检查并预占预算
→ 创建正式任务并固化执行参数与定价依据
→ Worker 调用正式 Provider 接口
→ 跟踪生成结果
→ 保存并交付视频
→ 按实际用量结算
```

### 4.2 应完成的功能

| 功能 | 职责 |
| --- | --- |
| 确认请求 | 确认当前请求与用户看过的预检结果一致；素材、Prompt、参数或适用规则变化后重新预检 |
| 正式准入 | 检查身份、生产权限、工作流是否启用、系统暂停状态和额度 |
| 素材上传与验证 | 校验素材归属、实际媒体信息及内容哈希，与有效预检记录核对；不能仅信任客户端声明 |
| 预算预占 | 根据当前请求和适用定价计算预占，在创建正式任务时一起完成，避免并发超额 |
| 正式执行 | Worker 将请求转换成对应工作流的 Provider 参数，调用正式生成接口 |
| 状态与恢复 | 跟踪排队、生成、失败等状态；重复提交不重复创建，已有 Provider 任务优先恢复查询 |
| 产物交付 | 保存生成视频、登记产物，让客户端能够下载和查看 |
| 费用结算 | 根据 Provider 实际用量和任务固化的适用价格计算费用，调整预占并保留明细 |

### 4.3 费用语义

预占金额和最终费用是两个值：预占用于提交前占用内部预算，最终费用按实际用量计算。

- Preview 估算、提交前复验和正式预占应使用一致的计算规则；价格或请求发生变化时，更新预检和确认依据。
- 定价需要体现模型、分辨率、是否含输入视频等适用因素，以及生效的优惠或账户价格。
- 不能把刊例价计算结果直接称为官方最终账单。
- 用量缺失时保留待核查状态，不能用预估值冒充实际费用。
- 失败或结果不确定时，结合 Provider 结果和计费证据处理预占，避免误结算。

### 4.4 执行、交付与防重复计费

- 生成结果和交付结果分别记录。
- Provider 已生成成功，但下载或归档失败时，恢复交付，避免重新生成。
- 提交超时或结果不确定时，保留任务信息并核实，不自动创建第二次付费调用。
- 用户继续等待、重新下载或客户端恢复时，复用原任务。
- 主动“再生成一版”属于新的生成意图，需要明确确认。

## 5. 工作流范围、启用状态与验证记录

本期确定开发的各类工作流，都要实现完整的 Preview 和 Production 链路。实际范围和实施安排维护在 [ROADMAP](../ROADMAP.md)。

以下三个维度应分开表达：

| 维度 | 回答的问题 |
| --- | --- |
| 能力支持 | 官方模型是否支持这个工作流和参数组合？ |
| 功能启用 | 当前系统是否已经实现并允许执行？是否临时暂停？ |
| 验证记录 | 做过哪些自动化测试、正式接口测试和真实出片验收？ |

“尚未真实验收”属于验证记录。开发完成后，应能通过有权限、受额度约束的 Production 路径完成首次正式验收，避免“必须先验收才能调用，但不调用又无法验收”的循环。普通使用的开放和受控验收仍须遵循服务端准入要求；本文不授权实际付费调用。

`disabled` 建议明确用于主动停用并附原因；“正在开发”“尚未验收”分别表达，不再混用。诊断性检查是否可用，与是否允许正式提交分开；诊断结果不得成为绕过停用状态的凭证。具体状态字段和迁移方案不在本次归档中决定。

支持指定输出时长的工作流，以实现 4–30 秒为目标，并逐项核对官方模型合同。编辑、延长等有特殊时长语义的工作流按官方合同处理，在 Preview 中解释清楚，不机械套用普通生成时长规则。

## 6. 完成定义

### Preview 完成

用户能在不上传、不生成、不预占的情况下，得到服务端校验过的请求摘要、费用估算或明确的估算缺口，以及正式提交条件。

### Production 完成

用户确认后，系统能够按该请求调用正式接口，正确处理素材、预算、执行、恢复、交付和结算。

### 单个工作流完成

两种模式均实现，关键契约验证通过，并有对应正式接口与真实产物验收证据。只有模板、参数检查或 payload 编译，不能算整个工作流完成。

具体符合性场景参考[统一需求规范 v2 的验收基线](../requirements/2026-09-15/workflow-preview-production-spec-v2.md#10-验收基线)；执行安排写入 ROADMAP，实现与验证证据写入 PROJECT_STATUS。
