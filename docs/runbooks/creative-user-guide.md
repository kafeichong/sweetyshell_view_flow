## 0. 拿到客户端后怎么装（macOS）

1. 把交付目录整个放到本机任意位置（**别只拷其中几个文件**）；
2. **双击 `install_creative.command`**；
3. 按提示选择 ComfyUI 根目录（脚本会自己找：常见位置 + **Comfy Desktop 的安装记录**；实在找不到会弹选择框，你选**里面有 `custom_nodes` 文件夹**的那一层。还找不到就双击同目录的 `诊断.command`，把输出发给管理员）；
4. 在弹出的隐藏输入框里粘贴**你自己的**个人凭证；
5. 看到"已安装完成（版本 …）"后，**完全退出并重启 ComfyUI**，然后搜索 `Video Flow` 导入模板。

安装器会覆盖 `custom_nodes/video_flow_client` 并把旧版本备份到 `ComfyUI/.video-flow-backups/`；它**只动这一个目录**，不碰你别的自定义节点。升级就是重跑一次这个安装器。

## 1. 当前能做什么

已经开放、可以正式生成的**七条工作流**：

| 模板文件（在 `custom_nodes/video_flow_client/workflows/` 里） | 用途 | 素材要求 | 5 秒 / 720p 的预占参考 |
| --- | --- | --- | --- |
| `seedance-text-to-video-preflight-v1.comfy.json` | 文生视频 | 无 | 7.623000 元 |
| `seedance-first-frame-to-video-preflight-v1.comfy.json` | 首帧生视频 | **恰好 1 张图** | 首帧比例命中标准表 7.623000 元；否则 7.747810 元 |
| `seedance-first-last-frame-to-video-preflight-v1.comfy.json` | 首尾帧生视频 | **恰好 2 张图**（首帧 + 尾帧，顺序固定） | 同首帧——只按**首帧**比例定 |
| `seedance-multi-reference-preflight-v1.comfy.json` | 全模态参考——**产品图 / 参考图也用它** | 图 ≤30、视频 ≤10、音频 ≤10，**合计 ≤50**，**至少 1 个**；视频、音频各自总时长 ≤30 秒 | 纯图 / 图+音 7.623000 元；**含输入视频 8.164800 元起**（视频时长越长越贵） |
| `seedance-audio-reference-preflight-v1.comfy.json` | 音频参考生视频 | **1–10 段音频**，总时长 ≤30 秒 | 7.623000 元 |
| `seedance-video-edit-preflight-v1.comfy.json` | 视频编辑 | **至少 1 段参考视频**（≤10 段），单段 4–30 秒 | 输出时长=输入视频时长、画幅随输入；5 秒输入视频约 **9.26 元** |
| `seedance-video-extend-preflight-v1.comfy.json` | 视频延长（接原视频续写 N 秒） | **至少 1 段参考视频**（≤10 段） | 延长 5 秒 + 5 秒输入视频约 **9.26 元**；输入视频越长越贵 |

> ⚠️ **`seedance-product-preflight-v1.comfy.json`（单参考图）已退休**：它的入口已关闭，提交会被服务端拒绝。产品图/参考图一律用**全模态参考**那个模板——只放一张图、其余槽位留在「（不给素材）」即可，服务端收到的是同一类任务。

**通用素材大小限制**：图片 <30MB、视频 ≤200MB、音频 ≤15MB（客户端会在选文件时就检查）。

**Preview 不花钱**：第一次 Queue 只做服务端预检（不上传素材、不生成），看过报价后**再 Queue 一次**才正式提交并计费。每次正式提交前看预检报告里的 `reserveCny`，那是这次会先预占的金额；实际结算以 Provider 返回的用量为准（通常与预占相差不到一帧的钱）。

**成片落在哪**：ComfyUI 的成片预览节点会直接给出视频控件；文件存在 ComfyUI 的 `output/video-flow/` 下，文件名带 `taskId`（报障要报这个 id）。

### 每条工作流的注意点

**文生视频**：时长 4–30 秒、比例 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16 / adaptive、分辨率 480p / 720p / 1080p、mp4 / mov、有声 / 无声、水印开关，**全部参数都开放**（1080p 也在授权内，价格按像素数成比例上涨）。

**首帧**：输出画幅跟随首帧（adaptive，模板固定）。首帧比例命中标准表（16:9 / 9:16 / 1:1 / 4:3 / 3:4 / 21:9）时报价锁定、最便宜；不命中会按"表内最大像素上界"预占（贵一点但安全方向）。**首帧裁成标准比例附近更省**。

**首尾帧**：**输出比例只按首帧锁定**——尾帧画幅与首帧不一致时会被拉伸，所以**首帧的比例比尾帧重要**。尾帧是否失真要自己看片确认。

**全模态参考**：槽位可以留空——模板预置了 4 个图、2 个视频、1 个音频槽位，每个下拉的第一项是「（不给素材）」；想用哪个就点开选文件，**不用的就留着别动，不需要删连线、也不需要旁路节点**。整套至少要选 1 个素材（官方要求）；一个都没选时节点会直接提示怎么改。要加更多素材，就把输入节点多摆几个、按 `reference_media` 串起来即可。

> 官方另有一条硬规则：**首帧、首尾帧、全模态参考是三种互斥场景**，`first_frame` / `last_frame` 与 `reference_image` 不能出现在同一个请求里。需要首尾帧就整条走首尾帧模板；全模态参考里想让某张参考图当首帧，只能在提示词里指定。
>
> 含输入视频时单价从 70 元/百万降到 42 元/百万，但计费秒数会加上输入视频时长，且官方有"最低用量"规则——图+2 秒视频 8.164800 元（最低值生效）、图+5 秒视频 9.109800 元，视频越长越贵。

**音频参考**：这是**纯音频**入口，只收 `reference_audio`——要混图片或视频请用全模态参考模板。**⚠️ 成片音轨不是传进去的那几段音频**：官方口径是"音轨由模型生成"（有声视频均为单声道，与传入音频的声道数无关）。这个工作流的产品语义是**用音频驱动画面**（口型、动作、节奏与音频对齐）；要保留原音，必须自己后期替换音轨。

**视频编辑**：输出时长不用选——**自动等于输入视频时长**（服务端固定 `duration=-1`）；画幅跟随输入视频；输出固定为 **mov**。提示词写清楚要修改的内容即可。

**视频延长**：提示词写法与其他模板不同，官方写法是「**在 @视频1 的基础上（向后）续写 N 秒的视频**，接着描述续写部分的内容」，**不要写时间戳分镜**。画幅自动跟随输入视频，输出固定为 mov。

> ⚠️ **延长返回的只是"延长出来的那一段"，不是完整视频**（已实测：输入 5.04 秒 + 延长 5 秒 → 成片 5.0 秒）。**需要你自己把它拼到原视频后面**——用任意剪辑工具接上即可，官方也说这是两步。

另外，在持有有效个人凭证且对原任务具有访问权限时，可以：

- 查询自己的已有 Task；
- 查看任务当前状态；
- 对已经交付完成的任务重新申请下载地址；
- 凭 `taskId` 向管理员或开发人员报告问题。

这些操作只读取原任务，不创建新的 Provider 请求，也不要求原预检仍有效、新任务额度充足或当前工作流仍启用。

## 2. 当前不要做什么

- 使用旧 `Seedance Preview` / `Seedance Production` / OneClick 节点或它们的旧模板——新节点在同名分类 `Video Flow` 下，旧节点一律不用；
- 使用已退休的**单参考图**模板 `seedance-product-preflight-v1.comfy.json`——服务端会拒，产品图/参考图走全模态参考模板；
- 在全模态参考模板里写"**把视频里的 X 换成 Y**""**延长 N 秒**"这类编辑/延长措辞——它提交的是"参考生视频"，模型按提示词判定成编辑/延长时任务会在提交**成功之后**异步失败（钱不白花，但白等一场）；**要编辑/延长请用对应的专用模板**；
- 因等待超时、下载失败或客户端重启而**重复提交同一次生成**——先查原任务（见第 5、6 节），重跑一次就是再花一次钱；
- 自行开启 Production 白名单、修改 `generation_version` 或额度试错。

**费用由服务端算，客户端改不了**。已开放授权覆盖"合同允许的全部参数组合"（480p/720p/1080p、各比例、4–30 秒、mp4/mov、有声/无声、水印），但**真实出片证据只覆盖部分参数面**（主要是 720p、16:9 附近、4–5 秒），其余参数是照官方公式外推——不在真实验收面的参数请先小成本试一两条再批量跑。

## 3. 提示词怎么写

官方（Seedance 2.5 提示词指南）给的结构是四段。**各工作流的提示词框里，默认值就是一段照这个结构写好的完整示例**——改成你的产品就行，不用从空白开始。

| 段 | 写什么 |
| --- | --- |
| ① 一句话概述 | 主体 + 地点 + 事件 + 题材/风格 + 特殊运镜 |
| ② 贯穿细节 | 主体长什么样、镜头是什么、全程要保持什么一致 |
| ③ 分镜 | 用时间戳（`0s-3s`、`3s-5s`）或「镜头 N」逐段写画面、运镜、动作、台词、音效 |
| ④ 结尾补充 | 机位、环境、声音、氛围 |

**示例**（默认 5 秒，与模板默认值同款）：

> 写实产品广告风格，干净柔和的棚拍光。在木质桌面上，一支银色保温杯缓缓旋转，水珠沿杯壁滑落。杯身金属质感清晰、logo 完整，桌面有自然倒影；镜头为近景，环绕运镜，始终让杯子保持画面中央。0s-3s：镜头贴近杯身缓慢环绕，水珠从杯口滑到杯底，金属反光随之流动。3s-5s：镜头拉远到中景，露出杯口升起的细微热气，杯子稳稳定在画面正中。低角度拍摄，浅景深，背景干净虚化；环境安静，只有轻微的水滴声与杯盖合上的轻响，整体干净、高级、有质感。

**分镜的三个注意点**：时间轴要连续（别写「0-3 秒…5-6 秒」）；每段别塞太满，塞满会导致过度剪切或漏剧情；**不要用时间戳控制频次**（比如「一秒摇头 3 次」）。改了时长（比如 30 秒）就把时间戳按新时长重排。

**镜头词直接用这些**（模型认识）：景别——远景/全景/中景/近景/特写；运镜——推/拉/摇/移/跟/环绕/俯冲/后拉/上摇/手持晃动；机位——低角度/俯视/第一人称。热门运镜也可以直接写：一镜到底、希区柯克变焦、航拍视角、FPV、子弹时间。**小众专业词要加一句解释**，例如「移焦，画面焦点平滑转变，前景的树由清晰变模糊」。转场要写清时间与方式：「第 5s 快速向左横向转场（向左擦除+自然叠化）」。

**长度**：中文建议不超过 500 字，太长模型会漏元素。

**想排除某些东西时**：只有**字幕**和**音频**支持反向描述——「不要字幕」「无 bgm，只生成环境音和动作音」；其余一律写成正向描述（比如「画面干净，没有杂物」）。

**带素材的模板**：用 `@图像1`、`@视频1`、`@音频1` 指代你放进槽位的素材（按放入顺序编号），例如「参考@图像1 的产品外观与配色，参考@视频1 的运镜节奏」。放了几样就写几样，没放的别写。**视频延长**例外，见第 1 节的官方写法。

## 4. 个人凭证安全

每位创意同事使用独立、可撤销的 actor token。

- 不共用凭证；
- 不把 token 写入 Workflow JSON；
- 不把 token 放进截图、文档、聊天或 Git；
- 不使用管理员或临时测试 token；
- token 丢失或怀疑泄漏时，停止使用并联系管理员撤销；
- 创意电脑不保存 Ark、OSS、数据库或 Worker 服务密钥。

客户端支持从安全配置或权限受限的 token 文件读取凭证。实际安装版本和目标 ComfyUI 实例必须由管理员确认，不能仅凭本仓库存在安装脚本就判断已经发布。

## 5. 查询已有任务

以下操作是只读查询。先由管理员提供实际 Backend 地址、个人 token 和原 `taskId`：

```bash
export VIDEO_FLOW_BASE_URL='https://ai.sweetyshell.com'
export VIDEO_FLOW_TOKEN='<个人 Token>'
export VIDEO_FLOW_TASK_ID='<原 taskId>'

curl -sS \
  "$VIDEO_FLOW_BASE_URL/api/v1/tasks/$VIDEO_FLOW_TASK_ID" \
  -H "Authorization: Bearer $VIDEO_FLOW_TOKEN"
```

结果只代表该 Task 当前记录，不会创建新任务。常见情况：

| 返回 | 含义 | 处理 |
| --- | --- | --- |
| `200` | 找到本人任务 | 查看任务状态和错误信息 |
| `401` | 没有有效身份 | 重新取得个人凭证，不要匿名重试 |
| `404` | 任务不存在或不属于当前账号 | 核对 `taskId` 和账号；服务端不会泄露他人任务 |

不要为了“看看任务是否还在”重新执行原生成画布。已有 `taskId` 时直接查询原任务。

## 6. 重新取得已有产物

对已经完成交付的原任务申请新的短期下载地址：

```bash
curl -sS \
  "$VIDEO_FLOW_BASE_URL/api/v1/assets/tasks/$VIDEO_FLOW_TASK_ID/result" \
  -H "Authorization: Bearer $VIDEO_FLOW_TOKEN"
```

常见结果：

| 返回 | 含义 | 处理 |
| --- | --- | --- |
| `200` | 产物已登记并可下载 | 使用返回的短期 `downloadUrl`；过期后重新调用本查询 |
| `401` | 凭证无效 | 联系管理员处理凭证 |
| `404` | 任务不存在或不属于当前账号 | 核对账号和 `taskId` |
| `409 RESULT_NOT_READY` | 原任务尚未形成可交付产物 | 继续查询原任务，不重新生成 |
| `409 RESULT_REQUIRES_REVIEW` | 原任务需要人工核查 | 向管理员提供 `taskId` |
| `409 DELIVERY_FAILED` | Provider 结果与交付状态不一致或归档失败 | 恢复原产物，不重新调用 Provider |

`objectKey` 是永久对象身份，不是可以直接粘贴到浏览器的公开 URL。下载地址过期不代表产物被删除。

## 7. 新 v2 Preview 的开发边界

v2 目标入口为：

```http
POST /api/v1/tasks/preflight
```

它只发送 Prompt、生成参数、素材元信息和内容哈希，不发送素材本体。报告应分别展示请求检查与 Production 准入，并返回 `willUploadMedia=false`、`willCallProvider=false`。

**你不需要手写这个请求**——客户端在 Queue 时会替你调它。这里写出来只是让你知道：Preview 阶段只发参数、素材元信息和哈希，**不发素材本体**；报告里的 `productionAdmission` 才是"能不能正式提交"的权威结论。

## 8. 什么时候需要管理员重新确认

下面这些情况不要自己处理，找管理员：

- **换了机器或重装 ComfyUI**：要重新跑一次安装器（版本号会变，凭证也要重新写入）；
- **换了账号或额度不够**：额度和生产白名单都是服务端配置，客户端改不了；报"额度不足"或 `PRODUCTION_NOT_ALLOWED` 时找管理员；
- **模板有更新**：版本号变了就要重新安装 + 重新导入模板，别混着用新旧节点；
- **要动没开放的模板**：工作流开关在合同里，只有管理员能改、并且要重新部署。

## 9. 报障信息

出现问题时至少提供：

- `taskId`；
- 使用的个人账号标识，不提供明文 token；
- 操作时间；
- 使用的 Backend 和客户端版本；
- ComfyUI 节点或接口返回的错误码；
- 是新生成、等待、查询还是下载阶段；
- 是否已经看到过 Provider Task ID 或产物。

没有明确确认“创建一个新生成意图”时，排障和恢复不得产生第二次 Provider create。
