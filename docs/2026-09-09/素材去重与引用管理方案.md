# 素材去重与引用管理方案

> 设计日期：2026-09-09  
> 核心问题：创意调参数时，如何避免素材重复上传？

---

## 一、问题场景

### 场景 1：创意调参数（同一张产品图）

```text
创意操作：
1. 上传 product.jpg → 生成视频 A
   Prompt: "产品从水面浮现"
   
2. 不满意，修改 Prompt → 生成视频 B
   Prompt: "产品从水面缓缓浮现，水花飞溅"
   
3. 还不满意，再修改 → 生成视频 C
   Prompt: "产品360度旋转展示"

问题：
❌ product.jpg 要上传 3 次？
❌ OSS 存储 3 份相同文件？
❌ 占用空间 × 3？
```

---

### 场景 2：多个任务复用同一素材

```text
创意操作：
1. 任务 A：product.jpg + Prompt A → 视频 A
2. 任务 B：product.jpg + Prompt B → 视频 B（不同效果）
3. 任务 C：product.jpg + Prompt C → 视频 C（又一个效果）

问题：
❌ 同一张 product.jpg 上传 3 次？
```

## 二、解决方案：基于文件哈希的去重

### 2.1 核心思路

```text
1. 创意上传文件
   ↓
2. 计算文件 MD5/SHA256 哈希
   ↓
3. 查询数据库：这个哈希已存在吗？
   ↓
4a. 已存在 → 直接返回已有的 OSS URL（秒传）
4b. 不存在 → 上传 OSS + 保存到数据库
```

**优点**：
- ✅ 相同文件只上传一次
- ✅ 节约 OSS 存储空间
- ✅ 节约上传时间（秒传）
- ✅ 统一管理素材

### 2.2 数据模型设计

```typescript
model MediaLibrary {
  id            String      @id @default(uuid())
  
  // ========== 文件唯一标识 ==========
  fileHash      String      @unique  // ✅ MD5 或 SHA256
  fileName      String               // product.jpg
  
  // ========== OSS 信息 ==========
  ossUrl        String               // https://oss.../abc123.jpg
  ossObjectKey  String               // media/2026/09/09/abc123.jpg
  
  // ========== 文件信息 ==========
  fileSize      Int                  // 1024000 字节
  mimeType      String               // image/jpeg
  
  // ========== 媒体元数据 ==========
  metadata      Json?
  /*
  图片：
  {
    "width": 1024,
    "height": 1024,
    "format": "jpg"
  }
  
  视频：
  {
    "duration": 5.2,
    "resolution": "1920x1080",
    "fps": 30
  }
  */
  
  // ========== 业务信息 ==========
  type          MediaType            // PRODUCT_IMAGE, REFERENCE_VIDEO, etc.
  tags          String[]             // ["产品图", "化妆品", "50ml"]
  category      String?              // "产品图" | "参考视频"
  
  // ========== 使用统计 ==========
  usageCount    Int         @default(0)   // 被使用了多少次
  
  // ========== 上传信息 ==========
  uploadedBy    String                     // 第一个上传者
  user          User        @relation(fields: [uploadedBy], references: [id])
  
  createdAt     DateTime    @default(now())
  
  // ========== 关联 ==========
  taskReferences TaskMediaReference[]      // 哪些任务使用了这个素材
  
  @@index([fileHash])       // ✅ 快速查找
  @@index([type])
  @@index([uploadedBy])
}

// ========== 任务与素材的引用关系 ==========
model TaskMediaReference {
  id          String      @id @default(uuid())
  
  taskId      String
  task        Task        @relation(fields: [taskId], references: [id])
  
  mediaId     String
  media       MediaLibrary @relation(fields: [mediaId], references: [id])
  
  // 引用类型
  role        MediaRole   // "input" | "reference" | "output"
  
  // 引用时间
  createdAt   DateTime    @default(now())
  
  @@unique([taskId, mediaId, role])  // 同一任务、同一素材、同一角色只引用一次
  @@index([taskId])
  @@index([mediaId])
}

enum MediaRole {
  INPUT       // 输入素材（产品图）
  REFERENCE   // 参考素材（参考视频）
  OUTPUT      // 输出结果（生成的视频）
}

// ========== Task 表改造 ==========
model Task {
  id              String      @id
  
  // ❌ 删除：inputAssets Json（不再直接存储）
  // ✅ 改为：通过 TaskMediaReference 关联
  mediaReferences TaskMediaReference[]
  
  // 其他字段保持不变...
  params          Json
  outputAssets    Json?
  ...
}
```

## 三、上传流程设计

### 3.1 前端上传流程

```typescript
// Frontend: packages/web/components/MediaUploader.tsx

async function uploadMedia(file: File): Promise<string> {
  // 1. 计算文件哈希（前端）
  const fileHash = await calculateFileHash(file);
  
  // 2. 检查是否已存在（秒传检测）
  const checkResponse = await fetch('/api/media/check', {
    method: 'POST',
    body: JSON.stringify({ 
      fileHash,
      fileName: file.name,
      fileSize: file.size
    })
  });
  
  const { exists, mediaId, ossUrl } = await checkResponse.json();
  
  if (exists) {
    // ✅ 文件已存在，秒传！
    console.log('文件已存在，秒传成功！');
    return mediaId;
  }
  
  // 3. 文件不存在，上传到后端
  const formData = new FormData();
  formData.append('file', file);
  formData.append('fileHash', fileHash);
  
  const uploadResponse = await fetch('/api/media/upload', {
    method: 'POST',
    body: formData
  });
  
  const { mediaId } = await uploadResponse.json();
  return mediaId;
}

// 计算文件哈希
async function calculateFileHash(file: File): Promise<string> {
  const buffer = await file.arrayBuffer();
  const hashBuffer = await crypto.subtle.digest('SHA-256', buffer);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  const hashHex = hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
  return hashHex;
}
```

#### API 2：上传新文件

```typescript
// POST /api/media/upload

import { prisma } from '@/lib/prisma';
import { uploadToOSS } from '@/lib/oss';
import { extractImageMetadata } from '@/lib/media';

export async function POST(req: Request) {
  const formData = await req.formData();
  const file = formData.get('file') as File;
  const fileHash = formData.get('fileHash') as string;
  
  // 1. 再次检查（防止并发上传）
  const existing = await prisma.mediaLibrary.findUnique({
    where: { fileHash }
  });
  
  if (existing) {
    return Response.json({ mediaId: existing.id, ossUrl: existing.ossUrl });
  }
  
  // 2. 上传到 OSS
  const ossObjectKey = `media/${new Date().toISOString().split('T')[0]}/${fileHash}.${getExtension(file.name)}`;
  const ossUrl = await uploadToOSS(file, ossObjectKey);
  
  // 3. 提取媒体元数据
  const metadata = await extractImageMetadata(file);
  
  // 4. 保存到数据库
  const media = await prisma.mediaLibrary.create({
    data: {
      fileHash,
      fileName: file.name,
      ossUrl,
      ossObjectKey,
      fileSize: file.size,
      mimeType: file.type,
      type: detectMediaType(file.type),
      metadata,
      uploadedBy: req.user.id,  // 当前用户
      usageCount: 0
    }
  });
  
  return Response.json({
    mediaId: media.id,
    ossUrl: media.ossUrl,
    message: '上传成功'
  });
}
```

```typescript
    await prisma.mediaLibrary.update({
      where: { id: mediaId },
      data: { usageCount: { increment: 1 } }
    });
  }
  
  return Response.json({ taskId: task.id });
}
```

```typescript
// POST /api/tasks

export async function POST(req: Request) {
  const { baseTaskId, mediaIds, params } = await req.json();
  
  if (baseTaskId) {
    // ✅ 基于已有任务创建（复制素材引用）
    const baseTask = await prisma.task.findUnique({
      where: { id: baseTaskId },
      include: { mediaReferences: true }
    });
    
    // 创建新任务
    const newTask = await prisma.task.create({
      data: {
        userId: req.user.id,
        workflowId: baseTask.workflowId,
        params: { ...baseTask.params, ...params },  // 合并参数
        parentTaskId: baseTaskId  // 记录父任务
      }
    });
    
    // ✅ 复制素材引用（不重新上传）
    for (const ref of baseTask.mediaReferences) {
      await prisma.taskMediaReference.create({
        data: {
          taskId: newTask.id,
          mediaId: ref.mediaId,  // ✅ 引用同一个素材
          role: ref.role
        }
      });
      
      // 增加使用次数
      await prisma.mediaLibrary.update({
        where: { id: ref.mediaId },
        data: { usageCount: { increment: 1 } }
      });
    }
    
    return Response.json({ taskId: newTask.id });
  }
  
  // 正常创建新任务...
}
```

### 4.2 方案 B：后端智能判断（备选）

```typescript
// PATCH /api/tasks/:id/params

export async function PATCH(req: Request) {
  const { taskId } = req.params;
  const { params } = await req.json();
  
  const task = await prisma.task.findUnique({
    where: { id: taskId }
  });
  
  // 判断：素材是否变化？
  const oldMediaIds = task.mediaReferences.map(r => r.mediaId).sort();
  const newMediaIds = params.mediaIds?.sort() || [];
  
  const mediaChanged = JSON.stringify(oldMediaIds) !== JSON.stringify(newMediaIds);
  
  if (!mediaChanged) {
    // ✅ 素材未变化，只是调参数
    // 直接更新参数，不重新上传
    await prisma.task.update({
      where: { id: taskId },
      data: {
        params: params,
        revisionCount: { increment: 1 }
      }
    });
    
    // 记录修改历史
    await prisma.taskRevisionHistory.create({
      data: {
        taskId: taskId,
        revision: task.revisionCount + 1,
        changedFields: detectChanges(task.params, params),
        newParams: params
      }
    });
    
    return Response.json({ message: '参数已更新' });
  } else {
    // ⚠️ 素材变化了，需要重新关联
    // ... 处理素材变更逻辑
  }
}
```

## 七、完整流程示例

### 场景：创意调整参数 3 次

#### 第 1 次（上传素材）

```text
1. 创意上传 product.jpg
   → 前端计算哈希: abc123...
   → POST /api/media/check { fileHash: "abc123..." }
   → 返回: { exists: false }
   → POST /api/media/upload (上传文件)
   → 返回: { mediaId: "media-001", ossUrl: "https://oss.../abc123.jpg" }

2. 创意创建任务
   → POST /api/tasks {
       mediaIds: ["media-001"],
       params: { prompt: "产品从水面浮现", duration: 5 }
     }
   → 创建 Task #task-001
   → 创建 TaskMediaReference: task-001 → media-001
   → media-001.usageCount = 1
```

---

#### 第 2 次（调参数，素材不变）

```text
1. 创意修改 Prompt
   → PATCH /api/tasks/task-001/params {
       params: { prompt: "产品从水面缓缓浮现", duration: 5 }
     }
   → 更新 Task #task-001 参数
   → 记录 TaskRevisionHistory
   → ✅ 素材引用不变（still: task-001 → media-001）
   → ✅ media-001 不重新上传
```

---

#### 第 3 次（继续调参数）

```text
1. 创意再次修改
   → PATCH /api/tasks/task-001/params {
       params: { prompt: "产品360度旋转", duration: 5 }
     }
   → 更新 Task #task-001 参数
   → 记录 TaskRevisionHistory (revision=2)
   → ✅ 素材引用依然不变
   → ✅ media-001 依然不重新上传
```

**结果**：
- product.jpg 只上传了 **1 次**
- OSS 只存储了 **1 份**
- media-001.usageCount = **1**（同一任务多次修改不重复计数）

## 八、总结

### ✅ 问题解决

| 场景 | 解决方案 | 效果 |
|------|---------|------|
| 创意调参数（同一任务） | 修改参数 API，不重新上传素材 | ✅ 素材不重复上传 |
| 多任务复用素材 | 基于 fileHash 去重 + 引用关系 | ✅ 相同文件只存一份 |
| 团队共享素材 | 素材库 + 秒传检测 | ✅ 任何人上传相同文件都秒传 |

```text
TaskMediaReference (引用关系)
```
