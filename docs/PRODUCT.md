# Video Flow 产品定义

> 状态：现行产品方向。
> 适用范围：Video Flow 的目标用户、核心问题、产品范围、非目标和完成判断。
> 文档职责：本文回答“为谁解决什么问题、产品做到什么程度”。强制行为见 `docs/requirements/`，当前实现见 [PROJECT_STATUS](./PROJECT_STATUS.md)，实施顺序见 [ROADMAP](./ROADMAP.md)，工程推进方法见 [DEVELOPMENT_WORKFLOW](./DEVELOPMENT_WORKFLOW.md)。

## 1. 产品定位

Video Flow 是公司内部的受控 AI 视频生成系统。创意同事继续在自己电脑上的 ComfyUI 中组织素材、Prompt 和生成参数，通过公司 Backend 与 Worker 统一调用已经授权的 Seedance 能力，并取得可以继续使用的视频产物。

产品需要同时解决四个问题：

1. 创意同事能够在熟悉的本地画布中完成生成，不直接接触 Ark 或 OSS 密钥；
2. 正式生成前能够看清实际请求、素材问题、费用依据和当前能否提交；
3. 公司能够统一控制身份、权限、额度、执行、费用和审计；
4. 网络、客户端或交付失败后能够恢复原任务，避免不明确地重复付费生成。

Video Flow 不是单纯的 Provider API 转发器，也不是只展示工作流模板的节点包。完整产品结果包括准备、检查、模式选择、执行、恢复、交付和费用解释。

## 2. 目标用户与职责

### 2.1 创意同事

主要产品用户。在本地 ComfyUI 中：

- 选择工作流；
- 输入 Prompt、生成参数和本地素材；
- 先执行 Preview，修正请求或了解 Production 阻止原因；
- 明确切换到 Production 后提交生成；当当前内容没有有效预检时，先自动完成一次只读 Preview；
- 等待、查询、恢复并下载自己的视频。

创意同事只持有可撤销的 Video Flow 凭证，不持有 Ark、OSS、数据库或 Worker 服务密钥。

### 2.2 管理员与运维人员

支持产品运行，但不代替创意同事完成日常画布操作。主要职责包括：

- 签发、撤销和核查用户凭证；
- 配置 Production 权限、暂停状态和额度；
- 处理费用未知、Provider 提交不确定、交付失败和告警；
- 部署、迁移、备份和回滚；
- 在明确授权范围内组织真实 Provider 验收。

### 2.3 开发与维护人员

维护 Backend、Worker、ComfyUI 客户端、工作流合同和验证体系。开发人员不能通过测试接口、客户端开关或手工改状态绕过正式准入，也不能把本地测试结果写成真实用户验收。

## 3. 核心用户场景

### 3.1 准备一次新的生成

用户在同一张画布中选择工作流，填写 Prompt、输出参数并选择本地素材。系统默认处于 Preview，不自动上传素材或触发付费生成。

### 3.2 Preview 检查和决策

本地插件读取实际文件并计算元信息与内容哈希；公司服务器统一检查请求、素材角色、数量、顺序和适用规则。用户应看到：

- 唯一的实际生效请求；
- 每项检查结果；
- 当前 Production 准入状态及阻止原因；
- 有依据的费用估算，或者明确的未知原因；
- Preview 不上传、不调用生成 Provider 的说明。

没有 Production 权限、系统暂停、额度不足或工作流尚未启用时，用户仍应取得请求检查结果，不能把准入问题冒充成请求格式错误。

### 3.3 切换 Production 并正式生成

新画布默认 Preview。用户主动切换到 Production 后，该模式保持不变，直到用户自己切回 Preview；系统不在每轮生成后强制重置模式，也不引入一次性确认按钮或确认实体。

Production 模式本身不是一次任务的身份，也不是服务端准入凭证。每个 Production 节点持有稳定的 `executionSlotId`；用户 Queue 时，系统仍须复验与当前内容匹配的有效预检、实际上传内容、权限、工作流启用状态、报价和额度。

如果当前内容没有有效预检，Production 模式下的本次 Queue 只自动执行 Preview 并停止，不上传素材、不创建 Task、不预占预算、不调用 Provider；用户查看报告后再次 Queue，才进入正式生成。只要内容、合同和报价仍与有效预检一致，连续“再生成一版”不要求重复 Preview。

### 3.4 等待和取得结果

用户能够看到自己的任务状态。Provider 成功后，系统保存并登记产物，用户从 ComfyUI 下载并使用可播放的结果。生成成功、归档成功和客户端下载成功是不同阶段，不能用一个模糊的 completed 掩盖交付失败。

同一执行槽在结果尚未成功下载、校验并由节点返回本地路径前，重复 Queue 只继续原 Task，不创建下一次生成。节点已经返回本地路径后，下一次普通 Queue 才表示“再生成一版”，创建新的 Task 并产生新的费用。

### 3.5 恢复已有任务

客户端退出、签名地址过期、预检过期、额度变化、Production 暂停或工作流关闭后，用户仍能在重新鉴权并通过原任务所有权校验的前提下继续查询、等待和下载已有任务。

恢复只处理原任务。查询不到结果、下载失败或 Provider 状态不确定时，不自动创建第二次生成。用户主动“再生成一版”属于同一执行槽中的下一次付费生成：每版对应一个新 Task；当前预检仍有效且内容未变时可复用，不强制重新 Preview。

### 3.6 管理和异常处置

管理员能够识别任务处于请求拒绝、预算不足、Provider 提交不确定、费用待核查、交付失败等不同状态，并采取不会造成重复付费的处置。暂停默认只阻止新的 Production，不阻止已有任务查询和必要的交付恢复。

## 4. 本期产品范围

### 4.1 工作流范围

以下八类工作流均以完整 Preview 与 Production 链路为开发目标：

1. 文生视频；
2. 参考图片生视频；
3. 首帧生视频；
4. 首尾帧生视频；
5. 全模态参考生视频；
6. 视频编辑；
7. 视频延长；
8. 音频参考生视频。

官方能力存在不等于产品已经实现；代码实现不等于已经启用；启用不等于完成真实验收。每个工作流分别记录能力、实现、准入和验证状态。

### 4.2 共用能力范围

本期包含：

- 同一画布的 Preview / Production 两种用户模式；
- Production 节点稳定执行槽、在途任务恢复和逐版顺序生成；
- 本地素材读取、元信息和哈希；
- 服务端请求、工作流和媒体规则检查；
- 可解释报价、预算预占、usage 解释和费用状态；
- 身份、所有权、生产权限、暂停和额度；
- 幂等提交、Provider 任务恢复和不确定提交处置；
- 输入/输出 Asset、OSS 归档、下载和交付恢复；
- Fake Provider 跨包验证、实际 ComfyUI 验收和受控真实 Provider 验收；
- 支撑安全运行所必需的部署、回滚、日志和异常处置。

### 4.3 关键产品边界

- Preview 是生成前检查，不是低清样片或免费的 Provider 生成。
- Production 是唯一允许调用正式生成 Provider 的用户路径。
- 模型、价格和 Provider 私有字段由服务端合同决定，客户端不能任意指定。
- 用户只能访问自己的任务和素材；管理员、Worker 与创意用户使用不同权限边界。
- 真实 Provider 调用、部署和生产开放必须单独授权，产品文档本身不构成授权。

## 5. 当前非目标

以下内容不是当前工作流完整闭环的必要前提：

- 在公司服务器集中部署或托管 ComfyUI；
- 完整的 Web 管理后台；
- 多 Provider 自动路由；
- 在线 Workflow 编辑器；
- 公司级 SSO；
- 自动拉取 Provider 最终账单并完成财务结算；
- 复杂审批流；
- 素材语义搜索、自动评分或创意质量判断；
- 由系统自动判断创意效果已经满足业务要求。

这些方向若进入开发，必须重新进行产品探索、需求确认和必要的架构决策，不能从现有基础能力自动推导为已批准范围。

## 6. 产品原则

### 6.1 安全默认

新画布默认 Preview，Production 必须由用户明确切换；切换后保持该模式，不自动回退。模式选择不能替代有效预检、服务端鉴权、准入和额度校验；没有这些检查的付费执行路径不得存在。

### 6.2 请求透明

用户看到的应是唯一实际生效请求。请求检查与当前 Production 准入分开表达，不能出现“参数通过但实际不能提交，却没有原因”的报告。

### 6.3 费用诚实

能够可靠估算时展示输入、规格、单价和适用条件；不能可靠估算时明确未知和缺失信息。估算、预占、usage 推算和 Provider 最终账单是不同费用状态。

### 6.4 不重复付费

稳定执行槽、服务端在途任务约束、幂等、Provider ID 持久化、提交不确定处理和交付恢复共同保证：一版尚未在本地完成交付时，客户端重试、Worker 重启或下载失败不能自动创建第二次付费生成。

### 6.5 结果可恢复

新任务准入和已有任务恢复是不同职责。价格、额度、预检或工作流启用状态变化不能阻止有权限的用户取回原任务结果。

### 6.6 证据边界

模板存在、函数测试通过、Fake Provider 通过、代码提交、线上部署、真实成片和创意同事接受必须分别记录。不能用前一层证据代替后一层。

## 7. 产品完成判断

### 7.1 Preview 完成

用户能够在不上传素材、不创建正式任务、不预占预算、不调用生成 Provider 的情况下，得到服务端检查过的实际请求、问题说明、报价或报价缺口，以及当前正式提交条件。

### 7.2 Production 完成

用户进入 Production 并具备与当前内容匹配的有效预检后，系统能够按冻结快照处理素材、权限、预算、正式执行、状态、恢复、交付和费用；失败或不确定时不会隐式重复生成，上一版在本地完成交付后才允许同槽创建下一版。

### 7.3 单个工作流完成

该工作流的 Preview 和 Production 均实现，关键合同与故障路径验证通过，并留下正式接口、真实产物、媒体信息和费用范围的验收证据。只有模板、参数检查或 payload 编译不能算工作流完成。

### 7.4 产品阶段完成

不能只用“所有测试全绿”判断产品完成。阶段结论至少分别说明：

- 需求与代码实现范围；
- 自动化测试和跨包合同；
- 实际 ComfyUI 安装与用户操作；
- 部署版本和生产配置；
- 真实 Provider、产物与费用证据；
- 尚未执行的用户接受和运营验证。

## 8. 待讨论的产品决策

以下事项在当前材料中没有形成足够明确的产品结论。本表不是实现任务；相关功能进入计划前应先讨论。

| 主题 | 需要确认的问题 | 触发讨论的时机 |
| --- | --- | --- |
| 首批用户和规模 | 首批由谁使用、同时使用人数、从 1 人灰度扩大到团队的条件是什么 | R8 发布和扩大准入前 |
| 工作流业务优先级 | 八类工作流的开发顺序是否只按技术依赖，还是需要按创意业务价值调整 | R6 逐项实施前 |
| 时间体验 | Preview 响应、任务状态刷新、生成等待和下载的可接受时间是多少 | 界面体验或监控指标设计前 |
| 预算目标 | 单任务、单用户、每日和每月的默认预算及提额流程是什么 | 正式开放和额度产品化前 |
| 内容和素材治理 | 素材授权、肖像、敏感内容和人工审核由谁负责，系统需要记录到什么程度 | 扩大真实素材使用前 |
| 产物留存 | 输入素材、产物、日志和费用证据保留多久，谁可以删除 | 正式运营和清理功能前 |
| 用户验收 | 哪些创意同事、哪些实际素材和什么结果可以判定用户侧接受 | 每个工作流真实验收前 |
| 管理体验 | 近期是否需要管理界面，还是继续使用脚本和接口 | 管理操作开始阻碍试点时 |
| Provider 范围 | 是否以及何时支持 Seedance 之外的 Provider | 提出第二 Provider 需求时 |

待讨论事项不阻止与其无关、需求已经明确的基础重构；一旦某项会改变当前切片结果，就必须在实现前完成讨论并更新本文或对应需求规范。
