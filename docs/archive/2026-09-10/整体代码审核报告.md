# Video Flow 整体代码审核报告

## 1. 审核结论

当前代码已经具备统一 Seedance 接入的架构雏形和较好的离线测试基础，但还不适合直接上线给同事使用。

主要风险集中在：

- 幂等创建存在并发竞态，可能产生重复任务
- Asset 上传票据失败会留下孤儿记录
- Worker 内部 service token 已定义，但实际状态回写仍使用旧接口
- Claim lease 字段已写入，但没有参与恢复和重新领取
- ComfyUI 示例 Workflow 目前还不可直接运行
- OSS object key 与临时签名 URL 的数据语义尚未完全统一

当前建议停留在 Preview 联调准备阶段，不进入真实 Production。

## 2. P0：上线前必须修复

### 2.1 幂等创建存在并发竞态

证据：

- `packages/backend/src/v1/tasks/v1-tasks.controller.ts:31`
- `packages/backend/src/tasks/tasks.service.ts:56`

当前流程是先查询 actor 和幂等键，再执行创建。两个并发请求可能同时查不到记录，然后同时创建。数据库唯一索引只能避免最终重复写入，但第二个请求会直接收到 Prisma `P2002`，当前没有转换为幂等成功或明确 `409`。

影响：

- 同一个 ComfyUI 请求可能产生两个任务
- 高并发时客户端收到 500
- Production 下可能造成重复付费

建议：

- 保留数据库唯一约束作为最终保护
- 捕获 Prisma `P2002`
- 捕获后重新查询同 actor、同 `clientRequestId`
- 请求体一致返回原任务，不一致返回 `409`

### 2.2 上传票据失败会留下孤儿 Asset

证据：

- `packages/backend/src/v1/assets/v1-assets.controller.ts:23`
- `packages/backend/src/assets/asset-presign.service.ts:6`

当前流程先创建 `Asset`，再检查签名服务。如果签名服务未配置或异常，接口返回 `503`，但数据库已经产生 `pending_upload` 记录。

影响：

- 数据库累积无法上传的 Asset
- 无法区分等待上传和票据生成失败
- 客户端重试会不断生成新 Asset

建议：

- 签名器不可用时不要创建 Asset；或者
- 引入 `ticket_pending -> ticket_issued -> uploaded -> failed` 状态流转
- 票据生成失败时将 Asset 标记为 `ticket_failed`
- 增加过期 Asset 清理任务

### 2.3 Worker service token 尚未真正保护状态回写

证据：

- `packages/backend/src/auth/worker-service.guard.ts`
- `packages/backend/src/v1/internal/v1-worker.controller.ts`
- `packages/worker/executor.py:174`

虽然已经建立内部接口和 `X-Worker-Token`，但 Worker 当前仍将状态回写到 `/api/tasks/:id`，并未使用 `/api/v1/internal/attempts/*`。

影响：

- Worker 仍依赖旧状态接口
- `VIDEO_FLOW_WORKER_TOKEN` 不是状态回写的强制条件
- 内部接口和真实运行行为不一致

建议先拆分 Worker 回写动作：

```text
record submission
record progress
record usage
complete
fail
requires review
```

拆分后再切换内部接口，不要保留“配置了 token 但实际不用”的假安全状态。

### 2.4 Claim lease 写入了，但没有参与恢复和重新领取

证据：

- `packages/backend/src/tasks/task-claim.service.ts:33`
- `packages/backend/src/tasks/task-claim.service.ts:74`

当前会写入 `leaseOwner` 和 `leaseExpiresAt`，但 claim 查询和恢复查询没有使用租约过期时间，也没有处理过期租约重新领取。

另外，Task 状态更新成功后，如果 `executionAttempt.create()` 失败，Task 可能已经变为 `submitted/in_progress`，但没有对应 Attempt。

建议：

- claim、Attempt 创建和租约写入保持在同一事务边界
- 过期租约允许重新 claim
- 恢复查询返回 lease 信息
- 增加租约过期和 Attempt 创建失败测试

## 3. P1：Preview 联调前建议修复

### 3.1 查询不到任务时返回 200/null

证据：`packages/backend/src/v1/tasks/v1-tasks.controller.ts:56`

`findOneForActor()` 返回 `null` 时，接口可能仍返回 `200 null`。

建议统一返回 `404`，避免客户端无法区分任务不存在、无权访问和查询成功。

### 3.2 v1 DTO 缺少运行时校验

证据：`packages/backend/src/v1/tasks/dto/create-task.dto.ts`

当前只有 TypeScript 类型，没有运行时校验：

- capability 是否允许
- profile 是否允许
- prompt 是否为空
- mode 是否只能是 preview
- params 大小和结构
- 上传 MIME、大小和文件名

建议接入 Nest `ValidationPipe` 与 `class-validator`。

### 3.3 没有正式的 actor token 创建流程

证据：`packages/backend/src/auth/credentials.service.ts:13`

`CredentialsService.create()` 已实现，但没有 Controller 或管理入口。当前只能手工写数据库，不适合作为同事安装和使用的正式流程。

建议增加受保护的管理操作：

```text
POST /api/v1/admin/credentials
```

要求明文 token 只返回一次，支持停用和轮换，且管理接口不能被普通 actor token 调用。

### 3.4 ComfyUI 示例 Workflow 不可直接运行

证据：`packages/comfyui-video-flow-client/workflows/seedance-image-to-video-v1.comfy.json:5`

当前 Workflow 使用 `image: null`，且 `links` 为空，尚未形成真实节点连接。

建议：

- 接入 `LoadImage`
- 连接 `LoadImage -> VideoFlowSeedancePreview`
- 连接 Preview 输出到 Wait 节点
- 用 ComfyUI API 格式导出真实 Workflow
- 在实际 ComfyUI 环境导入验证

### 3.5 Worker 结果 Asset 仍保存临时签名 URL

证据：`packages/worker/executor.py:447`

Worker 上传后将签名 URL 传入旧 Asset 创建接口，与“数据库永久保存 objectKey，签名 URL 按需生成”的设计不一致。

建议 OSS 上传器返回：

```text
bucket
objectKey
etag
sizeBytes
```

数据库只保存 `objectKey`，下载时重新生成签名 URL。

## 4. P2：后续迭代处理

### 4.1 OSS 签名服务仍是协议占位

证据：`packages/backend/src/assets/asset-presign.service.ts:18`

此前版本只是把 `OSS_PRESIGN_ENDPOINT` 拼接为 `/upload` 和 `/download`；当前已改为由 Backend 使用 `ali-oss` 直接生成预签名 URL。

这可以作为抽象边界，但不能视为 OSS 能力已经完成。

### 4.2 ComfyUI 客户端 HTTP client 没有关闭

证据：`packages/comfyui-video-flow-client/client.py:11`

节点执行时可能反复创建 `httpx.Client`，但没有显式关闭。长时间运行可能导致连接池和 socket 资源累积。

建议使用共享 client 或 context manager。

### 4.3 ComfyUI 节点可能把 token 保存进 Workflow

证据：`packages/comfyui-video-flow-client/nodes.py:13`

Token 作为普通 `STRING` 输入，可能被写入 Workflow JSON、历史记录或分享文件。

建议从本机环境变量读取 token，节点只配置 credential alias，不让明文 token 进入 Workflow。

## 5. 已完成验证

本轮审核前已执行：

- Backend Jest：9 个测试套件、29 个测试全部通过
- Worker 关键合同和恢复测试：5 个通过
- Prisma Client 已重新生成

尚未完成：

- ComfyUI 插件测试，当前插件环境没有安装 pytest
- Backend build
- 真实 OSS 签名服务联调
- 实际 ComfyUI 导入和执行
- 真实 HTTPS 和反向代理验证

## 6. 推荐修复顺序

```text
1. 修复幂等并发竞态
2. 修复 Asset 票据失败和 objectKey 持久化
3. 拆分 Worker 状态回写并真正启用 service token
4. 完善 lease 恢复逻辑
5. 增加 DTO 运行时校验
6. 修正 ComfyUI 可运行 Workflow
7. 再进行手动 Preview 联调
8. 最后进入 Production policy 和单人灰度
```

## 7. 当前发布判断

当前版本适合：

- 继续离线测试
- 准备测试环境
- 验证鉴权和幂等
- 验证数据库迁移
- 设计 OSS 签名服务

当前版本不适合：

- 直接给多人安装使用
- 直接开启 Production
- 执行真实 Seedance 付费调用
- 将当前签名 URL 作为永久资产地址保存
