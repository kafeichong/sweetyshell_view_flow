# 工作流 Preview 与正式生成统一需求规范（v1.1 历史快照）

- 版本：v1.1
- 确认日期：2026-09-14
- 需求来源：Steven 确认“先 Preview 验证填写完整、参数正确；通过后才明确提交付费生成”，并要求以后所有工作流遵循。
- 性质：强制产品与开发规范；不代表功能已经实现，不授权本次部署或付费生成。
- 当前实现与验证证据：[PROJECT_STATUS](../../PROJECT_STATUS.md)。实施计划：[ROADMAP](../../ROADMAP.md)。

## 1. 目标与适用范围

创意人员在同一张已连线的 ComfyUI 工作流中完成：选择素材、填写提示词与规格 → Preview 查看报告 → 明确确认正式生成 → 等待、下载、预览成片。

所有新建或改造的工作流必须遵守本规范，包括文生视频、参考图片、首帧、首尾帧、全模态参考、视频编辑、视频延长、参考音频，以及后续新增 Provider 或入口。已有工作流的规范适配按 ROADMAP 执行；不能因有历史成功记录而视为已符合本规范。

## 2. 执行模式

| 行为 | Preview 预检 | 正式生成 |
| --- | --- | --- |
| 检查提示词、参数、素材与工作流约束 | 必须 | 必须复验 |
| 读取本地素材、计算内容哈希和元信息 | 允许 | 必须核对与预检一致 |
| 调用本系统不执行生成的预检接口 | 完整预检必须调用，须鉴权 | 用于校验有效预检记录 |
| 上传素材到 OSS 或 Provider | 禁止 | 预检通过且明确确认后允许 |
| 创建可被 Worker 领取的生成任务 | 禁止 | 准入检查通过后允许 |
| 创建付费执行 Attempt、预占生成额度 | 禁止 | 按服务端规则执行 |
| 调用 Provider 生成接口 | 禁止 | 经服务端与 Worker 执行 |
| 等待生成、下载成片 | 跳过，并明确显示“未生成视频” | 查询原任务、下载已交付成片 |

Preview 是参数与素材检查，不是生成低清样片，也不是 Provider 试调用。“不产生费用”指不触发视频生成计费、不占用生成额度；不得承诺网络或服务器基础设施运营成本绝对为零。

Preview 通过仅代表已知规则检查通过；不能保证 Provider 最终受理、内容审核通过、出片成功或创意效果满意。

## 3. 同一画布与操作约束

- 沿用既有 Seedance-Ark 工作流的分步交互：运行方式、素材输入、校验、请求构建、请求预览、正式提交、等待、下载、预览保存。
- 模板预先连好线，不要求创意人员手动接线或切换到另一份 Production 模板。
- 默认模式为 `preview`，确认开关 `confirm_live_submission=false`。打开或导入模板不得触发真实生成。
- 一个运行方式节点控制全链路。Preview 可以经过相同节点链，但上传、生成、等待和下载不得执行外部副作用。
- 旧界面的 `live`、`production` 如需兼容，由适配层显式映射到服务端正式模式；具体枚举须依据实际节点版本确定。未知模式、缺失策略一律不得进入付费路径。
- Preview 通过后不得自动切换模式或自动提交。用户必须明确选择正式生成并确认。
- Token 通过本地安全配置提供，Ark/OSS 密钥只保留在服务器。创意人员不需要输入 assetId 或 Provider 字段。

## 4. 预检内容与报告

必须检查：

1. 提示词必填、类型、有效内容，以及当前工作流要求的其他字段。
2. 素材存在且可读取；实际类型、文件大小、图片尺寸、视频/音频时长及已取证规则要求的编码、帧率。
3. 素材数量、顺序、角色及组合；明确区分 `reference_image`、`first_frame`、`last_frame`、`reference_video`、`reference_audio`。
4. 时长、分辨率、比例和可选参数的取值、互斥关系与工作流专属约束，如 `adaptive`、编辑时长约束。
5. 工作流版本与服务端规则版本；所选参数是否属于允许范围。
6. 服务端鉴权、工作流开放状态、生产暂停状态及额度信息是否可获取。额度检查是当时的结果，不是额度预占或正式准入承诺。

报告必须显示通过项、失败项、无法验证项，错误定位到具体字段或素材，并给出修改建议。关键检查失败、未完成、服务端不可达时，不得显示“可正式提交”。

报告展示本次实际生效的提示词、素材摘要、角色与顺序、模型/工作流版本、生成规格、是否生成声音等影响结果的参数。禁止默默丢弃或替换用户填写的参数。费用若有可靠估算，应标明依据与非最终账单；无法估算时显示“未知”，不能显示 0 元。

`disabled` 不得获得可用于正式提交的预检通过记录；`preview_only` 的检查通过不等于有 Production 权限。普通创意入口仅允许已获生产准入的工作流；新能力真实验收按单独受控计划执行，同样必须遵守预检和确认要求。

### 4.1 本地与服务器的执行分工（强制）

每位同事只需在自己的 ComfyUI 安装一次客户端插件并配置个人 Token。插件自动完成本地检查和服务器预检请求；不要求同事安装 Backend、数据库、Worker，或手动执行检测命令。客户端检查依赖由安装流程统一检查和配置；必要依赖缺失时应提示修复，不能跳过检查后报告通过。

| 执行位置 | 必须承担的职责 | 信任边界 |
| --- | --- | --- |
| 本地 ComfyUI 插件 | 读取所选文件，确认存在、可读和可解析；提取实际格式、字节数、尺寸、时长等元信息，计算文件内容 SHA-256；按所用规则版本检查 | 文件未上传时，检查结果属于客户端上报信息 |
| 公司 Backend | 鉴权；检查提示词、字段类型、素材角色/数量/顺序、生成参数组合、工作流与规则版本、生产开放状态；返回报告并保存不可执行的预检记录 | 服务器统一规则是准入依据；不得把上报信息描述为服务端已检查文件内容 |
| 正式上传后的服务端检查 | 从实际上传对象核对文件内容哈希、类型、元信息及归属，并与有效预检记录匹配 | 不能仅比较上传请求或 OSS 自定义元信息中由客户端声明的哈希 |

### 4.2 Preview 请求与返回边界（强制）

- Preview 向公司服务器发送提示词、工作流标识与版本、生成参数，以及素材的角色、顺序、文件名或展示标识、元信息和内容哈希；请求包含鉴权信息，但凭证不进入检查报告或日志。
- 不发送素材文件本体、Base64 文件内容或缩略图，不提供让服务器在 Preview 阶段拉取素材的 URL；不上传到公司服务器、OSS 或 Provider。无需发送本机绝对路径。
- 新素材不要求预先取得 assetId。预检接口不得通过隐式调用上传接口来满足 assetId 要求。
- 服务器返回逐项报告及可供正式提交核对的预检记录标识；具体字段和端点由接口实现定义，不在本需求中虚构现有 API。
- 本地检查完成后，必须完成服务器检查才能显示完整 Preview 通过。断网、Token 无效、服务器检查失败或必要规则不兼容时，应显示“本地检查已完成，服务器预检未通过/未完成”，不得允许正式提交。
- 若客户端规则与服务器规则不一致，以服务器规则为准；必要时重新检查或升级插件，不允许每台电脑各自采用过期规则获得正式准入。
- Preview 保存的记录不可被 Worker 领取，不产生付费 Attempt，不预占生成额度，不请求 Ark 生成。

```text
本地选择素材、填写参数
→ 插件读取文件并检查，计算哈希和元信息
→ 仅向公司服务器发送参数与检查信息
→ 服务器校验统一规则并保存不可执行的预检记录
→ ComfyUI 显示报告
→ 用户明确确认正式生成
→ 上传素材、服务端核对实际内容与预检记录
→ 权限与额度等准入复验通过后，才进入 Provider 生成路径
```

## 5. 预检记录与一致性

- 预检成功须形成服务端可验证的记录，绑定 actor、工作流及版本、规范化提示词、全部生成参数、素材内容哈希/顺序/角色、规则与生产规格版本。
- 本地文件检查结果必须注明来源；在尚未上传时，服务端不能声称已经独立检查了素材内容。
- 正式提交必须引用有效且属于当前 actor 的预检记录。不得只信任客户端传入的“已通过”布尔值。
- 修改素材内容、数量、顺序、角色、提示词、生成参数、工作流，或服务端规则/规格发生变化，均使原预检失效。节点位置等纯画布布局变化不应使其失效。
- 正式上传的素材必须与预检哈希一致；服务端应根据实际上传文件再次校验类型、元信息、哈希和归属。失败时不得进入生成队列。
- 预检有效期由实现方案明确并测试；过期记录必须重新预检，不在此猜定具体时长。
- 网络失败、检查中断不得保留误导性的绿色通过状态。没有有效记录、记录失效或被篡改时，正式请求必须在服务端拒绝。

## 6. 素材资产与正式数据流

本系统 `assetId` 是内部素材编号，适用于产品图、视频、音频及生成产物。它不等于方舟资产库编号、`asset://` 引用或真人授权证明；不同命名空间不得混用。

Preview 使用本地文件哈希和元信息，不为预检强制创建或上传资产。正式确认后，上传服务生成或复用本系统 assetId，并关联到已预检的素材。产品素材无需走人物授权流程；涉及真人的授权条件须独立核对，不能以取得 assetId 替代授权。

正式数据流：

```text
有效预检记录 + 用户明确确认
→ 上传素材并复验（或复用已上传且属于当前 actor 的素材）
→ 服务端复验预检一致性、工作流准入、Token、额度及暂停状态
→ 冻结执行快照、登记任务与预算预占
→ Worker 调用 Provider
→ 保存生成结果到 OSS
→ ComfyUI 查询原任务、下载和预览
```

Provider 原生字段由服务端/Worker 按官方文档和原始示例构建；不得猜字段名、类型或响应结构，不允许 ComfyUI 绕过服务端直连付费 Provider。

## 7. 正式确认与重复计费保护

- 正式提交必须同时满足：本次内容预检通过、有效记录匹配、用户明确确认、服务端准入通过。
- 用户确认必须绑定本次生成意图；上一份内容的确认不能自动授权修改后的内容。
- 同一生成意图重复排队、超时重试、重启恢复时复用原任务和幂等标识。
- 继续等待、重新下载不需要新建生成任务，不再次扣生成额度。
- 创建结果不确定时保留可追溯信息并进入待核实处理，不自动创建第二次付费调用。
- 主动“再生成一版”必须是明确的新意图并重新确认；预检记录仍有效且内容相同时可复用检查结果，否则重新预检。
- 失败时展示 taskId（若已创建）、失败阶段、费用状态与下一步。不能把 Provider 成功但 OSS 下载失败描述成“未生成”，诱导重复付费。

## 8. 必须覆盖的验收场景

下表是需求符合性标准，执行排期与结果分别维护在 ROADMAP 和 PROJECT_STATUS。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 默认导入并运行模板 | Preview；不上传素材，Provider create=0，无可领取任务、付费 Attempt 或预算预占 |
| AC-02 | 必填字段缺失、类型错误、未知参数 | 定位错误；不得取得可正式提交的通过记录 |
| AC-03 | 文件缺失、损坏、规格越界、角色/数量/顺序错误 | 预检失败，不进入付费路径 |
| AC-04 | 正常 Preview | 返回完整报告、明确“未生成视频”；网络调用仅限允许的无生成副作用检查 |
| AC-05 | 跳过 Preview 直接正式提交 | 客户端提示，服务端也拒绝 |
| AC-06 | 预检后修改素材/提示词/参数或切换账号 | 原记录不再授权此次提交，必须重新预检 |
| AC-07 | 记录过期、规则版本变化、伪造通过标记 | 正式提交拒绝 |
| AC-08 | Preview 通过但未打开正式确认 | 不上传、不创建付费任务 |
| AC-09 | 有效预检且明确确认 | 上传后复验；服务端准入通过才创建一个生成意图对应的任务 |
| AC-10 | 上传文件与预检哈希不一致、跨账号资产 | 拒绝正式生成，无 Provider 调用 |
| AC-11 | 白名单不通过、额度不足、生产暂停、工作流未开放 | 正式提交拒绝；预检通过不得绕过这些检查 |
| AC-12 | 重复排队、请求超时、客户端重启 | 找回原任务；不自动重建付费任务，不确定提交进入核实 |
| AC-13 | 下载失败后重跑取片 | 查询并下载原产物，不再调用生成接口 |
| AC-14 | 主动再生成一版 | 新意图、再次明确确认；检查有效预检条件 |
| AC-15 | 同一画布在 Preview 下经过 Wait/Download 节点 | 安全跳过，不轮询模拟 ID，不伪造真实成片 |
| AC-16 | 产品素材上传与人物授权区分 | 内部 assetId 可用于产品；不得充当真人授权或方舟资产编号 |
| AC-17 | 本地检查成功、服务器不可达或拒绝鉴权 | 不显示完整 Preview 通过，不允许正式提交 |
| AC-18 | 检查 Preview 的出站请求及服务端调用 | 仅向公司服务器提交参数、元信息和哈希；无文件/缩略图/Base64 上传或 URL 拉取，无 Provider 生成调用 |
| AC-19 | 多台客户端的规则版本不同 | 由服务器统一规则检查；必要检查未完成时要求重新预检或升级，不能沿用过期规则通过 |
| AC-20 | 客户端声明的哈希与实际上传字节不同，但 OSS 自定义哈希相同 | 按实际内容校验拒绝生成，不能只信任声明值 |
| AC-21 | 新同事安装并使用 Preview | 一次安装客户端插件及配置 Token 后自动检查；无需本地后端或手动检测命令，缺依赖明确提示 |

验证必须结合客户端模式分支、Backend 真实 Guard/请求校验、Worker 不执行证明及隔离 Fake Provider 调用计数；不能只看 UI 显示或单测全绿。真实付费验收需要独立记录单次预算与授权范围，不因保存本需求而自动获得授权。

## 9. 后续开发约束

每个新增或改造工作流必须引用本规范，说明适用素材/参数规则、官方证据来源、预检报告、正式确认与幂等策略，并提供 AC 场景的验证证据。涉及接口变更时同步运行手册。

本规范优先于此前将 Preview 和 Production 拆成两份操作模板的设计。现状仍以 PROJECT_STATUS 为准，计划仍以 ROADMAP 为准；本规范不回填历史完成状态。
