## 二、架构设计优势

### 1. 职责清晰的五层架构

```text
① 创意生产层 (ComfyUI)
   - 负责"怎么生成"
   - 创意人员工作台
   
② Workflow 层
   - 负责"怎么生产"
   - 企业核心资产沉淀
   
③ AI 能力层 (Provider Gateway)
   - 负责"谁来生成"
   - 支持多 Provider 切换
   
④ 执行控制层 (Worker)
   - 负责"如何可靠执行"
   - 安全护栏 + 幂等控制
   
⑤ 管理资产层 (AI Studio)
   - 负责"管理整个生产过程"
   - Project → Campaign → Task → Asset
```

**设计亮点**：
- ✅ ComfyUI 不负责管理，只负责生成
- ✅ Workflow 与 Provider 解耦，避免供应商锁定
- ✅ Worker 作为连接层和安全层，保护生产环境

---

### 2. "图片先审，再转视频"的务实流程

```text
需求 → 分镜 → 图片 → 【人工审核】→ 视频 → 【人工审核】→ Asset
```

**业务价值**：
- 视频生成成本高（约 5-10 倍于图片）
- 产品外观错误需要提前在图片阶段发现
- 品牌视觉问题提前修正，避免视频返工

**这是商业级内容生产的核心差异点**。

---

### 3. MVP 范围控制

**第一阶段只做 4 个 Workflow**：
```text
① Text → Image
② Product Image → Scene Image
③ Image → Video
④ First Frame → Video
```

**核心业务链**：
```text
产品图 → Scene Image → Image Review → First Frame → Video → Asset
```

避免了范围失控，验收标准清晰可衡量。

## 三、关键阻塞问题分析

文档明确列出 5 个阻塞问题，**都是基础工程问题，可解决**：

### P0 级（立即解决）- 预计 1 周

#### 1. ComfyUI Runtime 连接失败
- **现象**：127.0.0.1:8188 connection refused
- **影响**：无法验证 ComfyUI 是否正常启动
- **解决方案**：
  ```bash
  # 1. 启动 ComfyUI
  cd /path/to/ComfyUI
  python main.py --listen 127.0.0.1 --port 8188
  
  # 2. 运行只读检查
  ./scripts/check-comfyui-runtime.sh
  ```
- **优先级**：🔴 最高

#### 2. Dry-run 输出契约未定义
- **现象**：Seedance 返回 `dry-run://video.mp4`，Worker 期待本地文件
- **影响**：Preview 模式无法验证
- **解决方案**：统一 Worker 与 ComfyUI 对 dry-run 的理解
  - **方案 A**：dry-run 生成本地占位文件
  - **方案 B**：dry-run 明确定义为不产生文件，只验证参数
- **优先级**：🔴 最高

---

### P1 级（尽快解决）- 预计 2 周

#### 3. Asset 注册未接入完整链路
- **现象**：当前 Asset 创建主要为独立测试
- **影响**：生成完成后无法自动登记到 AI Studio
- **解决方案**：
  ```text
  ComfyUI Complete
         ↓
  Worker Output Validation
         ↓
  Asset Registration (POST /api/assets)
         ↓
  AI Studio Database
  ```
- **优先级**：🟡 高

#### 4. Required Nodes 需要补齐
- **现象**：Runtime 检查未覆盖 Seedance 自定义节点
- **影响**：无法确认 Workflow 所需节点已注册
- **需要补齐的节点**：
  ```text
  SeedanceArkPromptBuilder
  SeedanceArkPreviewSaveVideo
  SeedanceArkExecutionPolicy
  SeedanceArkCreateTask
  SeedanceArkWaitTask
  SeedanceArkDownloadVideo
  ```
- **优先级**：🟡 高

---

### P2 级（需要完善）- 预计 1 周

#### 5. Quarantine 未持久化
- **现象**：失败任务的 quarantine 状态只在内存中
- **影响**：Worker 重启后状态丢失
- **解决方案**：
  ```python
  # 设计持久化方案
  persistent_submission_credential
  persistent_quarantine_state
  manual_intervention_state
  ```
- **优先级**：🟢 中

## 四、风险控制评估

### 1. 付费调用风险 ✅ 已控制

```python
# 默认关闭
COMFYUI_ENABLED=false

# Production 必须满足
mode=production
confirm_live_submission=True
明确 Provider
明确费用处理规则
```

**评估**：✅ 风险控制完善

---

### 2. 重复执行风险 ✅ 已控制

```text
如果已有 prompt_id → 只能查询 → 禁止再次提交
```

**评估**：✅ 幂等控制已实现

---

### 3. 输出路径风险 ✅ 已控制

Worker 已实现：
- 限制允许访问的输出目录
- 防止目录穿越
- 校验真实文件
- 校验文件类型

**评估**：✅ 安全机制完备

---

### 4. 多系统集成复杂度 ⚠️ 需关注

5 层架构需要严格的接口契约：
```text
ComfyUI ↔ Worker ↔ AI Studio ↔ Provider ↔ OSS
```

**建议**：
- 每个接口都要有明确的 schema 定义
- 每个阶段都要有失败恢复机制
- 每个边界都要有日志和监控

---

### 5. 外部依赖稳定性 ⚠️ 需关注

依赖第三方 AI 服务：
- Seedance
- Kling
- Veo
- Wan

**建议**：
- Provider 失败时有降级策略
- 记录每次调用的完整上下文
- 预留手动干预接口
