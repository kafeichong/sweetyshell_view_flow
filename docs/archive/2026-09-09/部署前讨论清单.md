---

### 2. 部署策略

#### 选项 A：独立部署（推荐）
```
新项目独立运行，使用独立端口和数据库
- Backend: 3100
- Worker: 8101
- DB: 独立容器
```
**优点**：
- ✅ 不影响旧项目
- ✅ 可以并行运行，逐步迁移
- ✅ 回滚简单

**缺点**：
- ⚠️ 占用额外资源

---

#### 选项 B：替换部署
```
停止旧项目，用新项目替换
```
**优点**：
- ✅ 节省资源
- ✅ 避免端口冲突

**缺点**：
- ❌ 无法回滚到旧系统
- ❌ 一旦有问题会影响生产

---

#### 选项 C：灰度部署
```
新旧系统并存，部分流量切到新系统
```
**优点**：
- ✅ 最安全
- ✅ 可以逐步验证

**缺点**：
- ❌ 配置复杂
- ❌ 需要流量分发机制

---

### 3. 数据迁移

#### 是否需要迁移旧数据？

**选项 A：全新开始**
- 新项目使用全新数据库
- 旧任务不迁移

**选项 B：迁移历史数据**
- 需要编写数据迁移脚本
- 将旧项目的 tasks 表数据导入新表
- 字段映射：
  ```
  旧表                新表
  workflow_hash   →  (丢弃)
  capability      →  (默认 IMAGE_TO_VIDEO)
  provider_profile → (默认 seedance)
  params          →  解析为 prompt + imageUrl
  actual_cost_cny →  cost
  error_message   →  errorMsg
  finished_at     →  completedAt
  ```

**建议**：选项 A（全新开始）
- MVP 目标是快速验证
- 历史数据迁移增加复杂度
- 如需查看历史，保留旧系统查询

### 5. 配置项确认

#### 必须配置的环境变量

```bash
# 数据库密码（强密码）
DB_PASSWORD=?

# 火山引擎 API Key
VOLCENGINE_ACCESS_KEY=你的火山引擎API_KEY

# 阿里云 OSS
OSS_ACCESS_KEY_ID=你的阿里云AccessKey_ID
OSS_ACCESS_KEY_SECRET=你的阿里云AccessKey_Secret
OSS_BUCKET=sweetyshell-ai-assets
OSS_REGION=oss-cn-beijing

# CORS（如果有前端）
CORS_ORIGIN=?
```

#### 可选配置
- Worker 轮询间隔（默认 5 秒）
- 任务重试次数（默认 3 次）
- 日志级别
