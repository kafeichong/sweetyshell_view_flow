## 二、需求拆解与深度分析

### 需求 1 拆解：创意部使用 ComfyUI

#### 2.1.1 真实使用场景

**创意人员的典型工作流**：
```text
1. 打开 ComfyUI（浏览器访问 127.0.0.1:8188）
2. 导入 Workflow（你提供的 .comfy.json）
3. 上传产品图
4. 调整参数：
   - Prompt（文案）
   - Duration（时长）
   - Ratio（比例）
   - Motion（运动幅度）
5. 点击 "Queue Prompt" → Preview
6. 查看结果，不满意重新调整
7. 满意后 → Production
8. 下载视频
```

#### 2.1.2 "工作流倒给他们"的含义

**问题 1**：你说的"倒给他们"具体是指？

**方案 A**：共享 Workflow 文件
```text
你做好 Workflow → 
发给创意部（.comfy.json 文件）→ 
他们手动导入 ComfyUI
```

**方案 B**：后台管理预装 Workflow
```text
你在后台管理系统上传 Workflow → 
创意部从列表中选择 → 
自动加载到 ComfyUI
```

**方案 C**：Workflow 模板库
```text
你维护 Workflow Library（数据库）→ 
创意部在后台看到所有可用 Workflow → 
点击"在 ComfyUI 中打开"按钮 → 
自动跳转并加载
```

#### 2.1.3 潜在问题

**问题 1：多人协作冲突**
```text
场景：
- 创意 A 在调参数（产品图 → 场景图）
- 创意 B 也在调参数（另一个产品）
- 两人同时用同一台 ComfyUI 机器（127.0.0.1:8188）

冲突：
- prompt_id 混乱
- 输出文件覆盖
- 无法区分谁的任务
```

**解决方案**：
- **方案 1**：每人独立 ComfyUI 实例（不同端口）
  ```text
  创意 A → 127.0.0.1:8188
  创意 B → 127.0.0.1:8189
  创意 C → 127.0.0.1:8190
  ```
  
- **方案 2**：共享 ComfyUI + Worker 隔离
  ```text
  所有人用同一个 ComfyUI →
  Worker 自动分配 client_id →
  根据 client_id 区分任务
  ```

**问题 2：参数调整后如何保存？**
```text
场景：
创意人员调了 20 分钟参数，效果很好

问题：
- 这些参数保存在哪？
- 下次怎么复用？
- 团队其他人能看到吗？
```

**解决方案**：
- **方案 1**：ComfyUI 自动保存（本地文件）
  ```text
  优点：简单
  缺点：无法共享、无法追溯
  ```

- **方案 2**：后台管理保存
  ```text
  创意调整完参数 → 
  后台提供"保存为模板"按钮 → 
  保存到数据库（Workflow Library）→ 
  其他人可以复用
  ```

**问题 3：创意部是否需要登录？**
```text
场景：
多人使用，需要区分谁生成了什么

需要：
- 用户管理（User 表）
- 权限管理（谁能用哪些 Workflow）
- 使用记录（谁用了多少次、花了多少钱）
```

### 3.3 视频存储 & 过期策略

**问题**：
```text
场景：
每天生成 50 个视频，每个 50MB

问题：
- 1 个月后存储多少？50 × 30 × 50MB = 75GB
- OSS 费用谁出？
- 旧视频要不要删除？
```

**解决方案**：

**方案 1：分层存储**
```typescript
model Asset {
  id          String      @id
  filePath    String
  ossPath     String?     // OSS 公网 URL
  
  status      AssetStatus  // LOCAL, OSS, ARCHIVED, DELETED
  
  expiresAt   DateTime?   // 过期时间
  
  storageSize Int?        // 文件大小（字节）
}

enum AssetStatus {
  LOCAL         // 只在本地
  OSS           // 已上传 OSS
  ARCHIVED      // 已归档（便宜的存储）
  DELETED       // 已删除（只保留元数据）
}
```

**策略**：
```text
生成后 7 天：本地 + OSS（快速访问）
7-30 天：仅 OSS（普通存储）
30-90 天：归档存储（便宜但慢）
90 天后：删除文件，保留元数据（追溯用）
```

**UI 界面**：
```text
后台管理 → 存储策略 → 
- 设置过期时间
- 设置归档策略
- 手动清理
```

### 3.5 失败重试 & 人工干预

**问题**：

**解决方案**：

**UI 界面**：
```text

建议操作：

✓ 重新提交

[查看原始 Prompt] [修改并重试]
```

**数据模型**：
```typescript
model Task {
  retryCount    Int      @default(0)
  maxRetries    Int      @default(3)
  
  parentTaskId  String?  // 重试的原任务
  
  failureType   FailureType?
  
  canRetry      Boolean  @default(true)
}

enum FailureType {
  CONTENT_POLICY   // 内容审核 - 需要修改 Prompt
  RATE_LIMIT       // 限流 - 可以自动重试
  INVALID_INPUT    // 参数错误 - 需要修改参数
  TIMEOUT          // 超时 - 可以重试
  PROVIDER_ERROR   // Provider 错误 - 可以换 Provider
  UNKNOWN          // 未知错误 - 需要人工介入
}
```

**自动重试策略**：
```python
# Worker 中
if failure_type in [FailureType.RATE_LIMIT, FailureType.TIMEOUT]:
    if task.retry_count < task.max_retries:
        await self.retry_task(task.id, delay=60)  # 1 分钟后重试
```

```typescript
// 前端每 5 秒查询一次
setInterval(async () => {
  const task = await fetch(`/api/tasks/${taskId}`)
  if (task.status === 'completed') {
    notify('视频生成完成！')
  }
}, 5000)
```

**方案 2：WebSocket**
```typescript
// Backend 推送
const ws = new WebSocket('ws://localhost:3000')

ws.on('task:updated', (data) => {
  if (data.taskId === currentTaskId) {
    updateUI(data.status, data.progress)
  }
})

// Worker 推送进度
await this.ws_client.send({
  event: 'task:updated',
  data: {
    taskId: task.id,
    status: 'running',
    progress: 45,  // 45%
  }
})
```

**方案 3：Server-Sent Events (SSE)**
```typescript
// Backend
app.get('/api/tasks/:id/stream', (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream')
  
  // 推送进度
  taskEmitter.on('progress', (data) => {
    res.write(`data: ${JSON.stringify(data)}\n\n`)
  })
})

// Frontend
const eventSource = new EventSource(`/api/tasks/${taskId}/stream`)
eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data)
  updateProgress(data.progress)
}
```

## 四、推荐的最小可行架构（MVP）

基于你的真实需求，这是我推荐的 MVP 架构：

### 4.1 核心组件

```text
1. ComfyUI (127.0.0.1:8188)
   - 创意部直接使用
   - 你提供 Workflow 文件

2. Worker (Python)
   - 监听 ComfyUI
   - 自动上传 OSS
   - 记录到数据库

3. Backend API (NestJS)
   - 任务管理
   - Provider 配置
   - 用户管理（简单）

4. 后台管理 (Next.js)
   - 查看任务列表
   - 配置 Provider API
   - 配置 OSS
   - 查看费用统计
```
