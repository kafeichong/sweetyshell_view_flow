### 1. 技术债务
旧项目可能存在的技术债务需要在迁移时清理。

### 2. 版本兼容性
检查依赖版本（Python 3.13、TypeScript 5.x、Next.js 14）。

### 3. 接口变更
旧 Backend API 与新需求的接口可能不完全兼容。

### 4. 测试覆盖
需要为新增功能（Image Review、Workflow Library）编写新测试。

## 结论

旧项目的 **Worker 模块、Workflow 文件、测试套件**是最有价值的资产，可以直接迁移并节约 **3-6 周**开发时间。

Backend 和 Web 需要根据新需求重新设计，但可以借鉴旧项目的架构思路。

**建议策略**：先迁移 Worker 核心，快速跑通端到端，再逐步补充新功能。
