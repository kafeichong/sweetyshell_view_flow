# Video Flow 项目现状分析与未来规划

> 分析日期：2026-09-11
> 分析视角：项目经理（范围 / 风险 / 里程碑 / 验收门禁）
> 分析方法：只读代码走查 + 实跑三个包的测试 + 交叉核对 docs/ 历史文档
> 本轮未修改任何业务代码、未部署、未调用任何付费 Provider

---

## 0. 一页结论

**现状：地基比文档写的更完整，但有一扇"公网可直接花钱"的门还开着。**

三句话总结：

1. **该有的骨架已经有了，而且质量不差。** 身份凭证（token 哈希存储）、预览/生产双模式、Production 白名单 fail-closed、幂等键 + 内容寻址、原子 claim + 租约、ExecutionAttempt 执行账本、OSS 预签名直传、内部 Worker 接口 —— 这些都是 09-09 文档里列为"缺失"的东西，现在代码里已经存在。测试实跑：Backend 56 通过 / 11 套件，Worker 78 通过 / 26 跳过，客户端 10 通过。
2. **但最重要的安全不变量没有闭环。** 旧的 `/api/tasks` 四个端点（创建、列表、单条、pending）**完全没有鉴权**，而 `POST /api/tasks` 写入的正是 Worker 唯一会领取并真实付费执行的 `status='pending'` 任务。这个接口经 `https://ai.sweetyshell.com/api/` 对公网可达。也就是说，v1 那套精心设计的"白名单 + 幂等 + 额度"体系，可以被一条不带任何凭证的 curl 绕过。
3. **产品闭环只走通了一半。** 真实付费出片已发生过（09-10，¥7.62，usage 推算），但产物交付是断的：输出 Asset 没有 ownerId / inspectionStatus，客户端拿不到下载链接；`Task.videoUrl` 里存的仍是 7 天后过期的 OSS 签名地址；客户端只有 Preview 节点，没有 Production 节点、也没有结果加载节点。

**因此我的建议是：不要进入"多人推广"，也不要急着开 Production 灰度。先做一周的"安全封口 + 基线固化"（Phase 0），再用 1–2 周做单人 Production 灰度（Phase 1），通过门禁后才谈多人开放。**

**最紧急的一件事（今天就能做，约半天）：给 `/api/tasks` 的四个无鉴权端点加上 Guard 或直接关闭。**

## 3. 规划总纲

### 设计原则

1. **资金安全优先于功能速度。** 任何"能让 Worker 真实花钱"的路径必须先有鉴权 + 额度两道闸门。
2. **一个阶段只开放一类用户。** Preview → 单人 Production → 小组 Production → 全员，每级都要过门禁。
3. **每个阶段都有可证伪的验收标准**，不做"差不多能用了"的判断。
4. **不追求功能广度。** 本期的唯一成功标准是：创意同事能安全、可追溯、可控制成本地自己出片。

### Phase 0：安全封口与基线固化（1 周）

**目标：把公网可付费面清零，让仓库回到干净可回归的状态。**

| 任务 | 对应风险 | 估时 |
| --- | --- | --- |
| 旧 `/api/tasks` 端点加 Guard 或下线（create/list/findOne/pending），更新上线 smoke 清单 | R1 | 0.5 天 |
| Compose + 云安全组端口收敛：只留 443 对外 | R2 | 0.5 天 |
| 提交未提交改动（客户端 review 修复 + docs + scripts），恢复干净基线 | — | 0.5 天 |
| 补 Worker 空 claim 响应处理（空 body / 204 不再打 JSON decode 错误并中断批次） | 计划 Task 2 | 0.25 天 |
| 建立 CI 三包全绿 + 修客户端 pytest 的 cwd 依赖 | R5 | 0.5 天 |
| 密钥卫生：清理 `.env.backup-token-*`，确认 `.env` 权限 | R10 | 0.25 天 |
| 文档收敛：废弃互相矛盾的现状描述，保留唯一权威现状文档 | — | 0.5 天 |

**Phase 0 出口门禁（全部满足才进入 Phase 1）：**

- [ ] 未带凭证访问 `https://ai.sweetyshell.com/api/tasks` 的 GET/POST 全部返回 401/403。
- [ ] 外部端口扫描只剩 443；Worker 与 PostgreSQL 无宿主端口。
- [ ] `git status` 干净，CI 三个包全绿且必过。

### Phase 3：平台化（可选，Month 2 之后）

只有当 Phase 2 门禁稳定通过、且出现明确业务需求时才启动：
